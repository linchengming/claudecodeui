# Claude 额度恢复后自动继续

在项目 `.env` 中启用，重启 CloudCLI 后生效：

```dotenv
CLOUDCLI_QUOTA_RETRY=true
CLOUDCLI_QUOTA_RETRY_INTERVAL_MS=300000
```

在 CloudCLI 中正常给 Claude 分配任务即可，交互对话和使用同一运行入口的定时消息都会生效。

- 遇到 API 限流、用量上限或额度耗尽时，默认每 5 分钟重新尝试，没有次数上限。
- Claude 提供明确的额度重置时间时，等待到该时间之后 5 秒再试；没有结构化时间时按间隔重试，不猜测账号的重置时刻。
- 页面显示下一次重试时间和次数。点击 **Stop** 立即取消等待；等待期间不占用 Claude 子进程。
- 已保存的会话会继续原任务，沿用工作目录、模型、推理强度与权限设置。继续提示会要求先检查已有结果，避免重复已完成操作。
- 认证错误、CLI 参数错误、普通崩溃、工具执行失败不触发此机制。不会自动换账号、换模型或购买额度。
- 目前仅为 Claude 运行入口启用；其它 provider 保持原行为。

等待在 CloudCLI 服务端运行，关闭浏览器不影响它。**电脑不能休眠，CloudCLI 进程必须保持运行**。当前等待状态不跨服务重启保存；重启后需要重新发送任务。此机制保证持续重试，不保证模型一定能正确完成任务或所有外部操作都可重复执行。

这份配置只影响本机 CloudCLI，不会改变系统其它位置的 Claude Code。`CLOUDCLI_QUOTA_RETRY=false` 并重启服务可关闭它。调用运行接口时也可用 `options.autoRetryQuota=false` 对单次运行禁用。

定时消息仍遵循 CloudCLI 现有的串行调度：某个定时任务一直等待额度时，后续定时/排队消息可能延迟。想继续同一夜间任务，发送一次完整任务即可，无需重复定时发送。

验证使用模拟错误与虚拟时钟，覆盖超过 5 小时的连续失败、恢复后继续、明确重置时间、停止等待和非额度错误，不需要耗尽真实账号额度。
