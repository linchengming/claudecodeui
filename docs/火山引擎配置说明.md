# 火山引擎（豆包大模型）配置说明

本文档说明如何在新电脑上配置 CloudCLI 接入火山引擎（豆包大模型）。

## 前置要求

1. 已安装 OpenCode CLI 1.x：`npm install -g opencode-ai@1.18.32`
2. 已克隆并配置 CloudCLI 项目
3. 已获取 API Key（当前走 sub2api 聚合网关，同一个 Key 覆盖豆包 / GLM / Kimi 等模型）

> 不要装 OpenCode 2.x（`@opencode/cli`）。2.x 的 `run` 不支持 `--dir` / `--variant`，且需要额外的 `opencode service set env` 才能拿到密钥，与 CloudCLI 当前调用方式不兼容。

## 配置步骤

### 1. 配置 OpenCode provider

创建 OpenCode 配置文件（如果不存在）：

**路径**：`C:\Users\<你的用户名>\.config\opencode\opencode.json`

**内容**：
```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "huoshan": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "火山 (sub2api)",
      "options": {
        "baseURL": "https://nd-sub2api.sdp.ndaeweb.com/v1",
        "apiKey": "{env:VOLCENGINE_API_KEY}"
      },
      "models": {
        "doubao-seed-evolving": {
          "name": "Doubao Seed Evolving",
          "limit": { "context": 1024000, "output": 256000 },
          "tool_call": true,
          "attachment": true,
          "reasoning": true,
          "modalities": { "input": ["text", "image"], "output": ["text"] },
          "variants": {
            "low": { "reasoningEffort": "low" },
            "medium": { "reasoningEffort": "medium" },
            "high": { "reasoningEffort": "high" }
          }
        },
        "glm-5.3-flash": {
          "name": "GLM 5.3 Flash",
          "limit": { "context": 200000, "output": 72000 },
          "tool_call": true,
          "attachment": true,
          "reasoning": true,
          "modalities": { "input": ["text", "image"], "output": ["text"] },
          "variants": {
            "low": { "reasoningEffort": "low" },
            "medium": { "reasoningEffort": "medium" },
            "high": { "reasoningEffort": "high" }
          }
        }
      }
    }
  }
}
```

以上只列了 2 个模型作为示例，本机实际配置了 6 个：`doubao-seed-evolving`、`doubao-seed-2.1-turbo`、`doubao-seed-2.0-code`、`glm-5.3`、`glm-5.3-flash`、`kimi-k2.6`。按同样结构追加即可。

三个容易写错的地方：

- `apiKey` / `baseURL` 必须放在 `options` 里面，写在 provider 顶层会被忽略。
- 环境变量引用语法是 `{env:VOLCENGINE_API_KEY}`，不是 `${VOLCENGINE_API_KEY}`。
- `baseURL` 必须带 `/v1` 后缀。
- `variants` 是**对象**（档位名 → 参数），不是数组。

### 2. 配置 CloudCLI 环境变量

编辑 CloudCLI 项目根目录的 `.env` 文件：

**路径**：`D:\CommonProject\claudecodeui\.env`（或你的项目路径）

**添加以下配置**：
```ini
# 火山引擎（豆包大模型，经 sub2api 聚合网关）
VOLCENGINE_API_KEY=你的API密钥
VOLCENGINE_BASE_URL=https://nd-sub2api.sdp.ndaeweb.com
```

### 3. 重启 CloudCLI 服务

双击运行：`tools\更新并重启.bat`

或手动重启（只杀 CloudCLI 自己的 node 进程，避免影响其他 Node 程序）：
```powershell
Stop-ScheduledTask CloudCLI
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'dist-server' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Start-ScheduledTask CloudCLI
```

### 4. 在 CloudCLI 中注册模型

OpenCode 侧配好后，还要让 CloudCLI 的模型下拉能看到它们。在 Web 界面的模型库面板添加自定义模型，id 用 `huoshan/<模型名>` 形式，例如：

| id | 显示名 |
| --- | --- |
| `huoshan/doubao-seed-evolving` | Doubao Seed Evolving (火山) |
| `huoshan/doubao-seed-2.1-turbo` | Doubao Seed 2.1 Turbo (火山) |
| `huoshan/doubao-seed-2.0-code` | Doubao Seed 2.0 Code (火山) |
| `huoshan/glm-5.3` | GLM 5.3 (火山) |
| `huoshan/glm-5.3-flash` | GLM 5.3 Flash (火山) |
| `huoshan/kimi-k2.6` | Kimi K2.6 (火山) |

### 5. 验证配置

先在命令行验证 OpenCode 侧是否通：
```powershell
$env:VOLCENGINE_API_KEY = '你的API密钥'
opencode run --format json -m huoshan/glm-5.3-flash "reply with: ok"
```
返回的 JSON 里出现 `"text":"ok"` 即为成功。

再验证 Web 端：

1. 打开浏览器访问 CloudCLI（本机为 `https://192.168.1.202:33001`）
2. 新建会话，provider 选 **OpenCode**
3. 模型下拉里选择带 `(火山)` 的模型
4. 发送测试消息验证是否能正常回复

## 配置说明

### 工作原理

- `server/load-env.ts` 在启动时把 `.env` 读入 `process.env`
- CloudCLI 调起 OpenCode CLI 子进程时会继承整个 `process.env`，所以 `VOLCENGINE_API_KEY` 会自动传给 OpenCode，**1.x 不需要执行 `opencode auth login` 或 `opencode service set env`**
- OpenCode 从 `~/.config/opencode/opencode.json` 读取 provider 配置，把 `{env:VOLCENGINE_API_KEY}` 替换为实际值
- 最终 OpenCode 通过 `@ai-sdk/openai-compatible` 用配置的 `baseURL` + `apiKey` 调用网关的 OpenAI 兼容接口

### 关于 sub2api 网关

`nd-sub2api.sdp.ndaeweb.com` 是一个聚合网关，对外暴露 OpenAI 兼容协议（`/v1/chat/completions`），背后转发到豆包、GLM、Kimi 等多家上游。所以这里只需要配**一个** provider 和一个 Key，模型名直接写上游名称即可。

注意 `/v1/models` 返回的清单并不完整（只列了 GLM 系列），**不能用它判断某个模型是否可用**。

### API Key 获取

从公司的控制台获取，或联系管理员。

### 常见问题

**Q: 找不到火山模型？**
- 检查 OpenCode 配置文件路径是否正确
- 用 `opencode models` 确认 `huoshan/*` 已出现；如果没有，检查 JSON 是否合法、`options` 结构是否写对
- 确认已在 CloudCLI 的模型库里注册了对应的自定义模型
- 重启 CloudCLI 服务后刷新浏览器页面

**Q: `opencode models` 列出的还是旧模型？**
- 检查当前终端有没有残留 `XDG_CONFIG_HOME` / `XDG_DATA_HOME`（指向其他目录会让 OpenCode 读错配置）：`Get-ChildItem Env:XDG*`，有就 `Remove-Item Env:XDG_CONFIG_HOME, Env:XDG_DATA_HOME` 后重试
- 确认工作目录下没有项目级 `opencode.json` 覆盖用户级配置

**Q: 报 503 `Service temporarily unavailable`？**
- 这是网关把上游的限流错误包了一层，真实原因通常是 `upstream_provider_rate_limit`，即该模型额度用尽或触发限流
- 不是配置问题，换个模型或等额度恢复即可

**Q: API 调用失败（401）？**
- `VOLCENGINE_API_KEY` 未传给 OpenCode 进程。Web 端由 `.env` 自动注入；手动跑 CLI 时需要先在当前终端设置该变量

**Q: 推理档位（reasoning effort）不生效？**
- `variants` 里的 `reasoningEffort` 是否真的被 `@ai-sdk/openai-compatible` 透传到请求体，尚未验证；档位可以选，但上游是否响应不保证
